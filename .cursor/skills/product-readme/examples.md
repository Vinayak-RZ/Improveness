# Product README — patterns to copy

Do not paste these products' copy. Steal **structure and density**. Do not point
skills at private disk paths at runtime.

## Installable agent / harness

What to copy:

- First screen: is / is not, **primary interface**, **invariant**, one **proof command**
- Era context with named papers the tree actually cites
- Core techniques: each has a **limit** and a verified link
- Optional field guide that teaches vocabulary (no numbered “The problem / Like”)
- Honest claims table or a claim ledger — omit numbers you cannot reproduce
- Get started after the teaching

What not to copy: 600-line landings for a 40-line SDK.

## Browser / localhost bridge

What to copy:

- One-line job (“turn X into Y”)
- Proof as two `curl`s (health + the write path)
- Isolation invariant in the blockquote (never share conversation across keys)
- Short mermaid of the idea, then pasteable install

## Offline advisor / library

What to copy:

- Product name vs import name stated once
- Proof that **ABSTAIN** (or equivalent fail-closed) is a first-class result
- Teaching captions under terminal blocks
- “Never auto-applies” as the invariant

## Public OSS density (optional)

Well-known public projects (short `pip`/`npm` install, one named technique with
a real blog, Go deeper instead of an API catalog) are density references only.
Do not copy their product names into the README you are writing.

## Length heuristic

| If the product is… | Aim for… |
|--------------------|----------|
| `pip install` / `npm` library | First screen + 1–3 techniques + install |
| Local engine / agent people run | Full order including field guide + honest claims |
| Both | First-screen contract, LangChain-short install after teaching |
